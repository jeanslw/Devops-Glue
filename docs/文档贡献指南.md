# Devops-Glue 文档贡献指南

本仓库的所有用户可见文档均采用**中英成对维护**：同一个文档有两种语言版本，文件名一一对应。改动任何一份文档，都必须在同一次提交中同步另一份，否则不予合并。

## 文档导航

- 入口是根目录的两个 README：
  - [中文 README](../README_ZH-CN.md) → 只列中文文档
  - [英文 README](../README.md) → 只列英文文档
- 新增 / 重命名文档后，**同时**更新两个 README 的「文档 / Documentation」表。

## 何时更新哪些文档

以一次功能变更（例如新增一项配置、一个新 API）为例：

| 变更类型 | 必更文档 |
|---|---|
| 新增 / 修改环境变量或配置 | 管理员手册「附录 A：环境变量完整参考」+ 该功能所在章节 |
| 新增 / 修改 API 端点 | API 文档对应模块 + 公开端点总表（若有） |
| 发布新版本 | 更新日志（ChangeLog / 更新日志）+ README 标题与 Release 徽标版本号 |
| 调整对外行为（鉴权、错误码、默认值） | 受影响文档的正文与示例全部核对 |
| 文档自身规范变更 | 本文档 + README 文档表 |

## 维护约定

1. **成对提交**：中文与英文文档在同一个提交中完成，互不领先。
2. **标题版本号一致**：README 与管理员手册标题中的 `vX.Y.Z` 必须与当前待发布版本一致；发布后更新到下一版本。
3. **英文写作规范**：使用英文母语者的常用表达，禁止逐字翻译中文句子；拿不准的表述先查证（如原文对应产品术语、既有文档先例），不自行发明译法。
4. **不翻译的名词**：环境变量名（`LDAP_ENABLED`）、权限键（`ci.manage`）、API 路径（`/api/rbac/users`）、字段名（`provider_uid`）、角色名、数据库表名一律保持代码原样，两侧语言均不翻译。
5. **交叉引用**：文档内链接一律使用文件相对链接（如 `[单点登录](单点登录.md)`）。重命名文件时必须全仓库搜索旧文件名，同步所有引用，避免死链。
6. **锚点链接**：目录链接（`#xxx`）的锚点需与目标标题一致。新增小标题后若使用中文锚点，请沿用同目录其它条目的写法并保持与标题逐字对应。
7. **示例即文档**：代码块中的请求 / 响应示例应与真实实现一致，随接口行为变化同步更新。
8. 小改动（修正笔误、补一句说明）与功能改动同等对待：仍须成对更新。

## 提交前检查清单

- [ ] 中文 / 英文文档均已更新，且内容一致
- [ ] 文档表（README_ZH-CN.md / README.md）与文件名对照表已同步
- [ ] 所有新链接可访问（相对路径正确、被引用文件存在）
- [ ] 环境变量、权限键、API 路径拼写与实现一致
- [ ] 若涉及发布：更新日志 + 版本标题 + Release 徽标版本号已就位

## 提交流程

- 在功能分支上完成文档与代码修改后，提交信息说明影响面（例如 `docs: 补充 LDAP 登录小节（中英）`）。
- 文档内容需接受代码评审同样标准的审阅：事实核对、措辞、成对一致性。
