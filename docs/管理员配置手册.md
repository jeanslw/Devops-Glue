## 1. 概述

Devops-Glue API 是基于 Slim4 的统一 API 层，为 Jenkins + GitLab CI 双通道构建、GitLab / Gitee / GitHub / Gitea 多平台代码、以及 Harbor 镜像仓库提供统一管理入口，覆盖从 CI 到 CD 的完整流程。它本身是 CI 增强组件，完整系统需配套部署服务 [Devops-Glue CD](https://gitee.com/jeanslw/devops_cd)。

| Devops-Glue API | Devops-Glue CD |
|:---:|:---:|
| v2.5.1 | v1.3 |
| v2.4 | v1.2 |

> 版本对应关系：Devops-Glue API v2.5.x 对应 CD v1.3，v2.4.x 对应 CD v1.2。可在管理面板「对接版本」页查看各平台的 API 版本。

---

## 2. 前置条件

| 组件 | 版本要求 |
|---|---|
| PHP | 8.0+（Docker 镜像使用 8.3） |
| 数据库 | SQLite（默认）/ MySQL 8.0+ / MariaDB 10.4+ |
| Jenkins | v2.60+ |
| GitLab | v9.0+（API v4） |
| Harbor | v1.10.1 / v2.x |

> **注意：** Jenkins / GitLab / Harbor 的 URL 必须从 Devops-Glue 容器内可访问。

## 4. 配置环境变量

```bash
cp config/.env.example config/.env
```

编辑 `config/.env`，至少填写以下关键项：

- **CI 系统**：`JENKINS_BASE_URL` / `JENKINS_USER` / `JENKINS_TOKEN`
- **Git 平台**：`GITLAB_BASE_URL` / `GITLAB_TOKEN`（以及 `GITHUB_*` / `GITEE_*` / `GITEA_*` 按需）
- **Harbor**：`HARBOR_BASE_URL` / `HARBOR_USER` / `HARBOR_PASSWORD`
- **管理后台**：`ADMIN_USER` / `ADMIN_PASSWORD`（首次启动创建根管理员账号）
- **数据库**：`DB_DRIVER` / `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS`（MySQL 时）

完整的环境变量清单与说明见 [附录 A](#附录-a环境变量完整参考)。

---

## 5. 准备数据库

支持两种数据库，由 `DB_DRIVER` 决定：

- `DB_DRIVER=mysql`：Docker Compose 会自动启动 MySQL 8.4 并创建数据库，同时完全兼容 MariaDB 10.4+。需在 `.env` 填写 `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS`。
- `DB_DRIVER=sqlite`：数据文件位于 `config/data/data.db`，无需额外数据库服务。生产环境建议使用 MySQL/MariaDB。

`DB_AUTO_MIGRATE` 控制建表方式：

- `true`（默认）：首次启动自动建表 + 写入种子数据。
- `false`：手动执行 `database/` 下的初始化脚本（`mysql_init.sql` 或 `sqlite_init.sql`），启动时仍会自动补种子数据。

## 6. 启动服务

**方式一：Docker Compose（推荐）**

```bash
cd docker-compose && docker compose up -d --build
```

**方式二：PHP 内置服务器**

```bash
php -S 0.0.0.0:8080 -t public/
```

启动后服务监听 `http://localhost:8080`。

## 7. 首次启动与自动初始化

首次启动时，系统会自动完成以下初始化：

1. **建表**：创建权限、角色、映射、用户、API Token 等全部数据表（`DB_AUTO_MIGRATE=true` 时）。
2. **种子数据**：写入内置权限、隐含规则、系统角色 `super_admin`。
3. **根管理员账号**：读取 `.env` 中的 `ADMIN_USER`（默认 `admin`）与 `ADMIN_PASSWORD`，创建拥有全部权限的 `super_admin` 账号。
4. **构建模式种子值**：读取 `BUILD_MODE`（默认 `both`）。

> 未设置 `ADMIN_PASSWORD` 时视为首次初始化，不会创建管理员账号，登录前需先在 `.env` 中设置密码。

## 8. 登录管理面板

浏览器访问 `http://localhost:8080/admin`，使用 `.env` 中的 `ADMIN_USER` / `ADMIN_PASSWORD` 登录。

- 右上角可切换界面语言（中文 / English）。
- 「修改密码」位于「用户管理 → 修改密码」。
- 管理员认证以数据库记录为准；只有 root 用户连续 3 次登录失败后，才会回退读取 `.env` 中的 `ADMIN_USER/ADMIN_PASSWORD`。

管理面板侧栏包含以下功能模块：

| 模块 | 说明 |
|---|---|
| 监测概览 | 数据概览与服务运行状态 |
| 映射管理 | Job ↔ Git ↔ Harbor 映射配置 |
| 安全审计 | SAST / 密钥 / 依赖漏洞扫描结果与回写记录 |
| 对接版本 | 各对接平台的 API 版本 |
| 配置模式 | 构建模式（jenkins / gitlab_ci / both） |
| 用户管理 | 用户列表、角色管理、修改密码 |
| 权限管理 | 权限列表、权限注册、隐含规则 |
| API 管理 | API Token 的创建 / 撤销 / 删除（需相应权限才显示） |

## 9. 接入 CI 平台

Devops-Glue 支持 Jenkins 与 GitLab CI 双构建通道。

**Jenkins**：在 `.env` 填写

```ini
JENKINS_BASE_URL=http://your-jenkins:8080
JENKINS_USER=admin
JENKINS_TOKEN=your_token
```

**GitLab CI**：复用 GitLab 平台配置（见下一步）。

配置完成后，在「监测概览」页确认服务连接正常。

---

## 10. 接入 Git 平台

在 `.env` 按需填写各平台的 `BASE_URL` 与 `TOKEN`：

```ini
GITLAB_BASE_URL=http://your-gitlab
GITLAB_TOKEN=your_token

GITHUB_BASE_URL=https://api.github.com
GITHUB_TOKEN=your_token

GITEE_BASE_URL=https://gitee.com/api/v5
GITEE_TOKEN=your_token

GITEA_BASE_URL=http://your-gitea
GITEA_TOKEN=your_token

DEFAULT_GIT_PLATFORM=gitlab   # URL 无法自动识别时的兜底平台
```

- 系统会根据仓库 URL 关键字自动识别平台；自建 GitLab/Gitea 域名通常缺少平台关键字，会降级到 `DEFAULT_GIT_PLATFORM`，因此建议显式配置。
- 需接入非内置平台时，参见 [附录 D](#附录-d自定义-git-平台接入)。

## 11. 接入 Harbor

在 `.env` 填写：

```ini
HARBOR_BASE_URL=http://your-harbor
HARBOR_USER=admin
HARBOR_PASSWORD=your_password
```

Harbor 用于关联构建产物（镜像仓库），并在安全审计中触发镜像扫描。

## 12. 配置构建模式

在「配置模式」页选择构建模式，取值：

- `jenkins`：仅使用 Jenkins
- `gitlab_ci`：仅使用 GitLab CI
- `both`：Jenkins 与 GitLab CI 并存

该值与 `.env` 中的 `BUILD_MODE` 对应，首次启动以 `.env` 为准，之后可在后台直接切换。

## 13. 配置映射

映射管理建立 Job ↔ Git 仓库 ↔ Harbor 镜像 三方关联，是 CI 数据聚合的核心。

### 自动发现

系统会自动扫描已启用的 CI 平台，并将发现的 Job 自动加入映射列表（初始为「待启用」状态，需手动启用）：

- `BUILD_MODE=both`：同时扫描 Jenkins 与 GitLab CI 的 Job
- `BUILD_MODE=jenkins`：仅扫描 Jenkins Job
- `BUILD_MODE=gitlab_ci`：仅扫描 GitLab CI Job

> **注意：** 当 `BUILD_MODE=both` 时，同一 `仓库地址` 可能出现重复条目（Jenkins 与 GitLab CI 各一条）。启用其中一条 pipeline（jenkins 或 gitlab_ci）后，另一条会自动隐藏；恢复为「待启用」状态时，重复条目会再次显示，这是正常逻辑。

### 手动映射

每个 Job 可配置以下字段。仅 `job_name` 为必填，其余字段可省略，由系统自动推导。

| 字段 | 必填 | 说明 |
|---|---|---|
| `job_name` | ✅ | Jenkins Job 或 GitLab CI 项目全路径，如 `"java/registry"` |
| `build_provider` | | CI 系统：`jenkins`（默认）/ `gitlab_ci` |
| `git_platform` | | **强烈建议**自建实例填写。省略时从 URL 关键字自动识别；自建 GitLab/Gitea 域名通常缺少平台关键字，会降级到 `DEFAULT_GIT_PLATFORM`。可选值：`gitlab` `gitee` `github` `gitea` 或自定义名称 |
| `git_remote` | | 省略时从 Jenkins Job SCM 配置自动获取 |
| `project_id` | | GitLab：省略时通过 API 自动查询；GitHub/Gitee：如已知请填写 |
| `web_url` | | 项目主页链接（仅展示） |
| `current_path` | | 项目路径；省略时从 `git_remote` 自动推导 |
| `harbor_repository` | | 关联的 Harbor 仓库，格式 `"project/repository"`（仅展示） |
| `api_version` | | **仅元数据用途**；不影响实际 API 路由（路由硬编码在各 Service 中） |

### 映射数据

示例（`config/settings.php`）：

```php
'job_git_map' => [
    // 自建 GitLab（域名无平台关键字 → 必须指定 git_platform）
    [
        'job_name'          => 'java/registry',
        'git_platform'      => 'gitlab',
        'git_remote'        => 'http://git.mycompany.com/tools/registry.git',
        'project_id'        => 2,
        'harbor_repository' => 'mycode/code-runtime',
    ],
    // SaaS Gitee（URL 含 gitee.com → 自动识别，git_platform 可省略）
    [
        'job_name'          => 'static',
        'harbor_repository' => 'mycode/static-app',
    ],
],
```

## 14. 权限与角色（RBAC）

Devops-Glue 采用数据驱动的 RBAC，权限键与隐含规则全部存数据库，可在后台直接管理。

### 内置角色与内置权限

- 系统内置唯一角色 `super_admin`，拥有全部权限，**不可删除**。
- 权限分「内置权限」与「注册权限」两类：内置权限随系统种子写入，**不可删除**；注册权限通过「权限注册」添加，**可删除**。
- 除 `super_admin` 外的角色（如 `admin` / `deployer` / `viewer`）由管理员在「角色管理」中自行创建并勾选权限。

### 创建角色与分配权限

1. 进入「用户管理 → 角色管理」，新建角色并命名。
2. 在权限树中勾选该角色可访问的权限。
3. 在「用户管理 → 用户列表」创建用户并分配角色。

### 权限注册

当新增 CD 菜单 / 模块需要新的权限键时，无需改代码，直接在「权限管理 → 权限注册」注册权限键（可指定父级键用于层级展示），注册后即可在角色编辑中勾选。权限列表会显示类型（内置 / 注册）与注册时间。

### 隐含规则

隐含规则定义权限的自动继承关系（子 → 父方向）。例如规则 `cd.bot → cd.notification-manage` 表示：勾选 `cd.bot` 时自动带上 `cd.notification-manage`，从而让对应菜单正确显示。

- 内置隐含规则随系统种子写入，**不可删除**。
- 用户通过「权限管理 → 隐含规则」新增的规则**可删除**。

## 15. 创建 API Token

API Token 供第三方服务（尤其是 Devops-Glue CD）或脚本调用 API 使用，独立于 RBAC 登录体系，直接携带接口权限（Scope）。

进入「API 管理」（需相应权限），创建 Token 时选择所需 Scope：

| Scope | 说明 |
|---|---|
| `main` | 只读：Job 列表、映射、Git 平台、Git 发现 |
| `git` | 只读：Git 分支 |
| `harbor.read` | 只读：Harbor 项目 / 仓库 / 标签 |
| `harbor.scan` | 触发 Harbor 镜像扫描 |
| `build.read` | 只读：构建流水线 / 日志 / 分支 |
| `build.write` | 写：触发 / 重试 / 取消构建 |
| `build.report` | 回写：scan-sync / commit-status |

> **注意：**
> - Token 明文只在创建成功时显示一次，请立即保存。
> - `/api/admin/*` 等管理端点一律禁止 API Token 访问（仅 super_admin 交互式登录可用）。

## 16. 对接 Devops-Glue CD

要让配套的 [Devops-Glue CD](https://gitee.com/jeanslw/devops_cd) 正常调用本系统，需在 Devops-Glue CD 的 `.env` 中配置指向本系统的连接。认证方式**二选一**：

**推荐 — API Token**（在「API 管理」为 CD 服务创建，建议授予其所需的 read / write / report Scope）：

```ini
CI_API_URL=http://devops-glue      # 本系统地址
CI_API_TOKEN=dg_xxx                # 上一步创建的 API Token
```

**已废弃 — 服务账号**（`CI_ADMIN_USER` / `CI_ADMIN_PASS`，将逐渐废弃，请优先使用 API Token）：

```ini
CI_API_URL=http://devops-glue
CI_ADMIN_USER=Service_Account      # 在后台创建的服务账号
CI_ADMIN_PASS=Service_Password
```

> 两种方式只能选其一，不可同时配置。

若与 CD 共用同一数据库，将 CD 的 `DB_HOST` 指向同一 MySQL 实例。

HARBOR_PASSWORD=your_password

# ============ 管理后台 ============

# 注意：
#   - super_admin 登录时，系统优先使用 admin_users 表中的 DB 记录验证。

#   - 如果你要为 Devops-Glue CD 服务创建独立账号，正确做法是先在后台创建对应账号并赋予 CD 权限，
#     然后再写入该 Devops-Glue CD 服务自己的 .env（前提是该 Devops-Glue CD 服务本身支持自己的 env 登录配置）。

# ============ 数据库 ============
DB_DRIVER=mysql               # sqlite 或 mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=devops_glue
DB_USER=root
DB_PASS=your_password
DB_PATH=config/data/data.db   # 仅 SQLite 使用
DB_AUTO_MIGRATE=true          # 自动建表；false = 手动执行 database/ 下的脚本

# ============ 应用 ============
APP_ENV=production            # production / staging / development
APP_DEBUG=false
API_BASE_URL=http://127.0.0.1:8080
LOG_PATH=/applogs/

## 附录 C：多环境部署

系统通过 `APP_ENV`（production / staging / development）支持环境隔离：

- `.env`：基础配置（含真实密码，gitignore 忽略）
- `.env.staging`：预发环境覆盖（如 `APP_DEBUG=true`）
- `.env.local`：本地覆盖（gitignore 忽略，个人调试用）

加载优先级：`.env.local` > `.env.{APP_ENV}` > `.env`

默认 `APP_ENV=production` 不需要额外文件。详见 `docs/技术文档.md`（中文）或 `docs/Technical-Guide.md`（英文）。

## 附录 D：自定义 Git 平台接入

无需修改核心源码即可接入任意 Git 平台。

### 1. 编写 Provider 类

在 `src/Service/Git/` 下创建适配器，实现 `GitProviderInterface`：

```php
namespace App\Service\Git;

class BitbucketService implements GitProviderInterface
{
    public function getName(): string { return 'bitbucket'; }
    public function matchUrl(string $url): bool { return str_contains($url, 'bitbucket'); }
    public function getApiVersion(): string { return 'v2'; }
    public function getBranches(string $repository): array { /* 分页拉取分支 */ }
    public function getTags(string $repository): array { /* 分页拉取 tag */ }
    public function setCommitStatus(string $repository, string $sha, string $state, string $context, string $description, string $targetUrl = ''): array { /* 回写 commit 状态 */ }
}
```

> `GitProviderInterface` 共 6 个方法，缺一不可：`getBranches`、`getTags`、`setCommitStatus`、`getName`、`matchUrl`、`getApiVersion`。

### 2. 在 `config/settings.php` 中注册

```php
'git' => [
    'custom_providers' => [
        [
            'class'  => 'App\\Service\\Git\\BitbucketService',
            'config' => [
                'name'         => 'bitbucket',
                'base_url'     => 'https://api.bitbucket.org/2.0',
                'token'        => env('BITBUCKET_TOKEN', ''),
                'api_version'  => 'v2',
                'matcher'      => function (string $url): bool {
                    return str_contains($url, 'bitbucket');
                },
            ],
        ],
    ],
],
```

### 3. 自动发现

无需修改其他源码。系统启动时自动发现并注册自定义 Provider。

> **注意：** 自定义平台不支持独立的 `.env` 变量（如 `BITBUCKET_TOKEN`）。Token 需直接写入 `settings.php`，或自行扩展 `AppConfig`。

### 4. 添加内置平台

如需添加内置平台（GitLab/Gitee/GitHub/Gitea 级别），需修改：

- `src/Service/Git/XxxService.php`（适配器）
- `config/container.php`（ProviderRegistry 注册）
- `config/AppConfig.php`（`getXxxConfig` + `getDefaultApiVersion` + `getGitPlatformsConfig`）
- `config/settings.php` + `settings.example.php`（配置段）
- `config/.env.example`（环境变量声明）
