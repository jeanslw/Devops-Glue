# 对接服务版本兼容性说明

> 本文档列明 Devops-Glue 各对接服务（Jenkins / GitLab / Gitea / Harbor）的版本支持情况、关键版本边界。
> 所有版本边界均依据各服务官方文档 / 发布说明核实。
> 文档版本：v2.7（2026-08-31）

---

## 总览

| 服务 | 最低支持版本 | API 版本 | 认证方式 | 是否需探测版本号 |
|---|---|---|---|---|
| Jenkins | v2.60+ | REST `/api/json`（无版本号） | Basic Auth（`user:token`） | 否（API 长期稳定） |
| GitLab | v9.0+ | v4（`/api/v4`） | `PRIVATE-TOKEN`（个人访问令牌 PAT） | 否（v4 自 9.0 稳定至今） |
| Gitea | 1.x 系列 | v1（`/api/v1`） | `Authorization: token` | 否（v1 长期稳定） |
| Harbor | v1.10.1 / v2.x | v1 / v2.0 | Basic Auth（账号/密码 或 secret） | **是** |

**核心结论**：Jenkins / GitLab / Gitea 三家的 API 版本号长期稳定。

---

## 1. Jenkins

### 1.1 版本支持情况

| 版本 | 支持状态 | 说明 |
|---|---|---|
| < 2.60 | ❌ 不支持 | 需 Java 7 或更旧，低于官方 Java 8 基线 |
| 2.60+ | ✅ 支持（最低） | 首个要求 Java 8 的 LTS 基线（2017-06） |
| 2.96（weekly）/ 2.107（LTS）+ | ✅ 支持 | 使用 API token + Basic Auth 的请求不再需要 CSRF crumb |
| 2.129+ | ✅ 推荐 | 新 API token 系统（SHA-256 哈希存储、多命名 token、可撤销） |
| 2.176.2+ | ⚠️ 注意 | crumb 仅对创建它的 web 会话有效，脚本需保留会话 cookie |
| 2.555.x（当前 LTS） | ✅ 推荐 | crumb 计算已移除客户端 IP，token 支持过期日期 |

### 1.2 关键版本边界（据官方发布说明 / 升级指南）

| 版本 | 事件 |
|---|---|
| 2.60（2017-06，LTS） | 首个要求 **Java 8** 的版本（最低支持基线） |
| 2.96 / 2.107（2018） | **API token + Basic Auth 请求免 CSRF crumb** |
| 2.129（2018-07） | **新 API token 系统**：token 以 SHA-256 哈希存储、可建多个命名 token、可单独撤销；legacy token 被高亮提醒轮换 |
| 2.138.1 | API token 系统改进 |
| 2.176.2（2019，LTS） | **crumb 与 web 会话绑定**：脚本需保留 session cookie 才能在后续请求复用 crumb |
| 2.543 / 2.555.1（2025） | crumb 计算移除客户端 IP（代理兼容）；API token 支持过期日期 |

### 1.3 Devops-Glue 的兼容策略

- **认证**：Basic Auth（`JENKINS_USER` + `JENKINS_TOKEN`），新旧 token 系统均适用（两者都是 `user:token` 的 Basic Auth）。
- **CSRF crumb**：代码已统一处理——触发构建（POST）遇到 403 时，自动请求 `/crumbIssuer/api/json` 获取 crumb 并携带 cookie 重试，因此同时兼容「开启/未开启 CSRF」「2.96 前后」各版本。
- **最低版本**：`v2.60`（Java 8 基线）。低于 2.60 的实例建议先升级（至少到 2.60）。

## 2. GitLab

### 2.1 API 版本演进（据官方 `doc/api/v3_to_v4.md`）

| 版本 | 事件 |
|---|---|
| 9.0（2017-03） | **API v4 引入**，成为首选版本 |
| 9.5（2017-08） | API v3 标记为 unsupported |
| 11.0（2018-06） | **API v3 移除**，此后仅保留 v4 |
| 至今 | 唯一 API 版本为 **v4**，根路径 `/api/v4` |

- 向后不兼容变更要求 API major 版本号变化；当前仍为 v4，因此 **v4 API 自 9.0 起持续向后兼容**。
- GraphQL 与 v4 REST API 并存；若未来出现 v5，将是基于 GraphQL 的兼容层。

### 2.2 GitLab 版本策略（据官方 Maintenance Policy）

- 版本号遵循语义化版本 `(Major).(Minor).(Patch)`。
- **Major**：每年一次，默认每年 5 月（如 18.0=2025-05、19.0=2026-05）。
- **Minor**：每月一次（每月第三个周四）。
- **Patch**：每月两次（月度 minor 前后各一个周三）。
- **维护策略**：
  - bug fix 仅 backport 到**当前 stable** 版本；
  - 安全修复 backport 到**当前 stable + 前两个月度版本**；
  - **无旧 major 的长期支持**（官方鼓励始终运行最新 stable）。
- **跨 major 升级**：不保证无缝，需先升到当前 major 的最新 minor，再跨到下一 major。

### 2.3 Devops-Glue 的兼容策略

- **最低支持版本**：GitLab `v9.0`（API v4 起点）。
- **API 版本**：固定使用 `/api/v4`，无需探测版本号（v4 稳定）。
- **认证**：`PRIVATE-TOKEN` 请求头（个人访问令牌 PAT）。
- **项目路径**：调用 `/projects/{id}` 时项目路径需 URL 编码（代码已处理）。
- **建议**：因 GitLab 官方只维护最新 stable（安全补丁仅覆盖当前 + 前两个月度版本），生产环境请升级到受支持版本；但就 API 集成而言，9.0 及以上的 v4 均可正常工作。

## 3. Gitea

### 3.1 版本支持情况

| 项 | 说明 |
|---|---|
| API 版本 | **v1**（根路径 `/api/v1`），API v2 暂无计划 |
| 版本线 | 社区版 1.x 系列（1.21 ~ 1.26，截至 2026） |
| 认证 | `Authorization: token <token>` 请求头 |
| 认证变更 | 通过 `?token=` 查询参数的认证方式在 **Gitea 1.23** 弃用，建议使用 `Authorization` 请求头 |

### 3.2 关键版本边界

| 版本 | 事件 |
|---|---|
| 1.x 早期 | API v1 引入，长期稳定，无 v2 分裂 |
| 1.23 | `token` 查询参数认证弃用（Devops-Glue 用 `Authorization` 请求头，不受影响） |

### 3.3 Devops-Glue 的兼容策略

- **API 版本**：固定使用 `/api/v1`，无需探测版本号。
- **认证**：`Authorization: token <token>` 请求头（Gitea 兼容 GitHub 的认证风格）。
- **最低支持版本**：Gitea 1.x 系列（API v1 稳定，无版本分裂）。

## 4. Harbor

Harbor 与其他三家不同，存在 v1→v2 API 大分裂与机器人账户 JWT→secret 的演进，因此需要探测具体版本号。

- 探测具体版本号（`/api/v2.0/systeminfo` 的 `harbor_version`，匿名优先、认证兜底）。
- 根据版本号判断机器人账户支持情况（边界 v2.2.0）。

详见《管理员配置手册》「接入 Harbor」一节。

| Harbor 版本 | 机器人账户是否可用于 REST API |
|---|---|
| v1.x / v2.0.x / v2.1.x | ❌ 不支持（JWT，仅 Docker/Helm CLI） |
| v2.2.0+ | ✅ 支持（secret，可 Basic Auth） |

## 5. 兼容策略总结

| 服务 | 是否需要版本探测 | 兼容关键点 | 代码现状 |
|---|---|---|---|
| Jenkins | 否 | CSRF crumb、新旧 API token | ✅ 已处理（`getCrumb()` 自动重试） |
| GitLab | 否 | PAT 认证、项目路径编码 | ✅ 已处理（`PRIVATE-TOKEN` + urlencode） |
| Gitea | 否 | `Authorization: token` 认证 | ✅ 已处理 |
| Harbor | 是 | v1/v2 分裂、机器人账户边界 | ✅ 已处理（版本探测 + 机器人账户判断） |
