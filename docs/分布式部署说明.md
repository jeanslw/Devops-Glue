## 2. 单镜像双角色容器

同一 `devops-glue` 镜像按挂载的 supervisor 配置分为两种角色：

| 角色 | supervisor 配置 | 进程 | 端口 | 副本数 |
|---|---|---|---|---|
| **Web** | `config/docker/supervisord.conf` | nginx + php-fpm | 80（可经 LB 暴露） | 1..N（无状态，可水平扩展） |
| **Worker** | `config/docker/supervisord-worker.conf` | 4 个 sleep-loop CLI | 无 | **1**（单实例） |

Worker 复用 Web 镜像，只把 `supervisord-worker.conf` 以只读方式挂载到 supervisor 读取的同一路径（`/etc/supervisor/conf.d/supervisord.conf`），无 `ports` 映射、无需重新 build。**所有 CLI 必须以 `www-data` 运行**：若以 root 运行，root 会抢先创建 root 属主的 SQLite 库文件，导致 php-fpm（www-data）写入失败。

## 3. Worker 定时任务一览

| program | CLI | 启用开关 | 间隔环境变量（默认） | 分布式租约锁 |
|---|---|---|---|---|
| `tag-cleanup` | `cli/cleanup-pipeline-tags.php` | 后台开关 `stale_tag_cleanup_enabled`（「系统设置」） | `TAG_CLEANUP_INTERVAL`（3600s） | ✅ `lock:tag-cleanup` |
| `tag-backfill` | `cli/backfill-pipeline-tags.php` | 后台开关 `backfill_tag_enabled` | `TAG_BACKFILL_INTERVAL`（1800s） | ✅ `lock:tag-backfill` |
| `api-log-cleanup` | `cli/cleanup-api-access-logs.php` | 「系统设置 → 平台管理 → 日志设置」的 DB 配置；保留天数未设置时回退 `API_ACCESS_LOG_RETAIN_DAYS`（默认 90） | `API_ACCESS_LOG_CLEANUP_INTERVAL`（86400s） | ✅ `lock:api-log-cleanup` |
| `db-backup` | `cli/backup-db.php` | 根 .env `DB_BACKUP_ENABLED`（默认关） | `DB_BACKUP_INTERVAL`（86400s） | —（无锁，靠 worker 单实例 + 开关门控） |

- 清理范围：`api-log-cleanup` 清理 `ci_api_access_logs` + `ci_operation_logs`（共用保留天数与开关）；**部署日志归 CD 系统所有，不在 CI 侧清理**。
- 备份输出：`db-backup` 复用 `DataBackupService`，启用 CD（共享库存在 `cd_*` 表）时产出两份 zip（`devops-glue_<driver>_<stamp>.zip` + `devops-cd_<driver>_<stamp>.zip`），各自独立恢复、互不牵连；写入 `BACKUP_DIR`（镜像内 `/data/backups`），两个前缀各自滚动保留最新 10 份。
- 开关未开启时各 CLI 打印「跳过」并退出 0，不产生副作用——扩容/迁移期间可安全关闭。

## 4. 分布式租约锁（ci_cache 行级锁）

定时任务跨实例幂等的核心：`Database::tryAcquireLock($name, $ttl=600)` / `releaseLock($name, $token)`，基于 `cache` 表、以 `cache_key`（`lock:<name>`）为主键的租约锁。MySQL 多实例或 SQLite 共享单文件均适用。

**抢占协议：**
1. 先 `DELETE` 已过期租约（`expires_at <= now`，即持有者异常退出 / 任务超时未续约）；
2. 再普通 `INSERT` 写入自己的租约——唯一键冲突说明存在有效锁，返回 `null`，CLI 打印「跳过」退出 0；
   - **不用 upsert/REPLACE**：那会在冲突时删旧行再插入，等于「偷锁」，破坏互斥；
3. `value` 存持有者 token（`host:pid:随机 4 字节`），`releaseLock` 按 `cache_key + value` 精确删除——任务超时被接管后，原持有者不会误删新持有者的租约；
4. TTL（600s，按单轮任务耗时约定）到期自动过期：崩溃的持有者不会死锁，下个调度周期可被接管。

**CLI 侧约定：** acquire 失败 → 打印跳过、`exit 0`；任务结束（成功或失败）在 `finally` 中精确释放。⚠️ 不得在 `try` 块内 `exit`——PHP 的 `exit` 会跳过 `finally`，导致锁不释放（只能等 TTL 过期兜底）。

## 5. docker-compose 水平扩容

- Web 共享配置抽取为顶层 `x-web-common: &web-common` YAML 锚点；**每个新副本只需一行 `<<: *web-common` 继承**，不必复制整段；
- 注释版 `devops-glue-web-2` 副本模板：放开注释即可得到第二个无端口 web 副本；
- `front-nginx` 负载均衡服务 + `config/docker/nginx-lb.conf`：轮询 `upstream glue_backend`、WebSocket/SSE 升级透传（`Upgrade`/`Connection` map）、`X-Forwarded-For` / `X-Forwarded-Proto` 头、`proxy_buffering off`（SSE 友好）。

**扩容步骤**（compose 文件内有对应注释）：
1. 注释掉 `devops-glue` 的宿主端口映射（web 改为仅容器内 80，统一走 LB 入口）；
2. 放开 `devops-glue-web-2` 副本模板；
3. 放开 `front-nginx` 服务段，并在 `nginx-lb.conf` 的 upstream 中放开对应 `server devops-glue-web-2:80;` 行。

**要点：**
- 应用不使用 PHP session，web 副本**无需粘性会话**；
- LB 会改写客户端 IP：必须在根 .env 设 `TRUSTED_PROXY_HOPS=1`，真实客户端 IP 才能进入登录失败限流与审计日志；
- 数据卷已共享（见 `x-web-common` 顶部注释），副本无需单独挂载。

## 6. Kubernetes 参考（config/k8s/devops-glue.yaml）

| 对象 | 说明 |
|---|---|
| `devops-glue` Deployment | Web 角色，`replicas: 3`（无状态，改 replicas 即扩缩，无 session 无需粘滞） |
| `devops-glue-worker` Deployment | Worker 角色，`replicas: 1`（定时任务单实例化；supervisord-worker.conf 以 ConfigMap 注入） |
| `front-nginx` | LoadBalancer 入口（LB 配置以 ConfigMap 挂载） |
| `devops-glue-app-env` Secret | `app.env` 注入 |
| MySQL StatefulSet（可选） | 集群内数据库 |
| PVC（RWX） | 备份目录 / SQLite 单文件共享 |

**⚠️ 多副本 OIDC 陷阱：** 必须在 Secret 中注入**固定**的 `OIDC_RSA_PRIVATE_KEY`（`openssl genrsa 2048` 生成后写死）。否则每个副本启动时会各自自动生成签名密钥，Jenkins / Harbor / GitLab 经 OIDC SSO 校验 token 时会因签名钥不一致而失败。

## 7. 数据库与备份注意

- **SQLite**：多副本必须共享**同一个**库文件（RWX 卷 / NFS）；否则各副本各持一份数据，必然不一致。生产多副本推荐 MySQL。
- 定时任务的跨实例幂等由租约锁保证（见 §4），与「单 worker 容器」的部署约束互为双保险。
- 备份与恢复流程与标准线一致（`cli/backup-db.php` / `bin/restore.php`），见《管理员配置手册》。

本变体的升级方式为**随主干重建**（而非长期并行合并）：

```
git checkout -B release/<X>-distributed release/<X>     # 从主干新基线切出
```

主干文档升级时变体自动继承；只有上表所列特征文件需要人工确认无冲突。本文档描述变体特征，随变体一起维护。
